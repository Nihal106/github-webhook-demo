# 10. Configuring GitHub Webhooks with Jenkins on AWS EC2

This lab configures **Jenkins on an Ubuntu EC2 instance** and uses a **GitHub webhook** to automatically trigger a Jenkins job whenever code is pushed to GitHub.

## 1. Objective

By the end of this lab:

```text
Developer
    ↓
git push
    ↓
GitHub
    ↓
Webhook
    ↓
Jenkins on EC2
    ↓
Jenkins Job
    ↓
Build automatically
```

We will **not use ngrok**, because Jenkins is running on a publicly reachable EC2 server.

# 4. Configure Security Group

Create a security group:

```text
jenkins-sg
```

Add these inbound rules:

| Type | Port | Source | Purpose |
|---|---:|---|---|
| SSH | 22 | My IP | Connect to EC2 |
| Custom TCP | 8080 | 0.0.0.0/0 | GitHub → Jenkins |

For this lab, port `8080` needs to be reachable from the internet because GitHub must send the webhook request to Jenkins.

> In production, you would normally put Jenkins behind HTTPS/reverse proxy or another controlled access layer rather than exposing port 8080 directly.

# 10. Install Jenkins

Add the Jenkins repository key:

```bash
sudo wget -O /etc/apt/keyrings/jenkins-keyring.asc \
  https://pkg.jenkins.io/debian-stable/jenkins.io-2026.key
```

Add the repository:

```bash
echo "deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc]" \
  https://pkg.jenkins.io/debian-stable binary/ | sudo tee \
  /etc/apt/sources.list.d/jenkins.list > /dev/null
```

Update packages:

```bash
sudo apt update
```

Install Jenkins:

```bash
sudo apt install jenkins -y
```

These are the current Jenkins LTS Debian/Ubuntu installation steps. [Jenkins](https://www.jenkins.io/doc/book/installing/linux/?utm_source=chatgpt.com)

# 29. Configure Payload URL

If your Jenkins URL is:

```text

```text

### Do NOT use:

```text

```

because that uses port `80`.

### Use:

```text

```

The GitHub Jenkins plugin uses the general endpoint:

```text
<JENKINS_BASE_URL>/github-webhook/

# 41. Troubleshooting

## Problem 1: GitHub says "Failed to connect to host"

Check the webhook URL.

It must include `8080`:

```text
http://<EC2-PUBLIC-IP>:8080/github-webhook/
```

Not:

```text
http://<EC2-PUBLIC-IP>/github-webhook/
```

---

## Problem 2: Jenkins doesn't open

Check:

```bash
sudo systemctl status jenkins
```

It should show:

```text
Active: active (running)
```

Then check:

```bash
sudo ss -lntp | grep 8080
```

---

## Problem 3: Security Group blocking connection

Check:

```text
EC2
 ↓
Security
 ↓
Security Groups
 ↓
Inbound Rules
```

Make sure:

```text
Custom TCP
Port: 8080
Source: 0.0.0.0/0
```

exists for this lab.

---

## Problem 4: Webhook succeeds but build doesn't start

Check Jenkins:

```text
Job
 ↓
Configure
 ↓
Build Triggers
```

Make sure:

```text
☑ GitHub hook trigger for GITScm polling
```

is enabled.

Also verify:

```text
Repository URL
Branch
```

are correct.

---

## Problem 5: Jenkins can't clone GitHub

For a public repository, verify the repository URL:

```text
https://github.com/<USERNAME>/<REPOSITORY>.git
```

For a private repository, configure appropriate GitHub credentials in Jenkins.

# 42. Important Difference: Webhook vs Credentials

Don't confuse these two.

### Webhook

```text
GitHub
   ↓
Jenkins
```

Purpose:

**Tell Jenkins that an event happened.**

### Git credentials

```text
Jenkins
   ↓
GitHub
```

Purpose:

**Allow Jenkins to access the repository.**

So:

```text
Webhook = Notification
Credentials = Authentication
```

---

# 43. Webhook vs Polling

### Polling

```text
Jenkins → GitHub
"Any changes?"

Jenkins → GitHub
"Any changes?"

Jenkins → GitHub
"Any changes?"
```

### Webhook

```text
Developer
    ↓
git push
    ↓
GitHub
    ↓
"Jenkins, there is a new push!"
    ↓
Jenkins
    ↓
Build
```

Webhooks are event-driven, so Jenkins doesn't need to repeatedly check GitHub. The GitHub plugin's trigger uses the incoming webhook event to initiate the relevant SCM check/build. [Jenkins Plugins](https://plugins.jenkins.io/github?utm_source=chatgpt.com)
